For Code

Build notes — how this slots into the repo

Follows the existing data model in data.js and the CLAUDE.md conventions. The front garden is a separate nav tab with its own map; beds reuse the existing BedDetail / PlantCard views.

1 · New view + nav

Add a fourth chrome button “Front garden” in app.jsx; new view state { name:"frontplan" }. Build FrontGardenPlan.jsx as a clone of GardenPlan.jsx with its own hardcoded order + legend arrays.

2 · ZONES (data.js)

Add frontEntrance, frontWallBed, frontCornerBush, frontBoundaryBed — same shape as existing zones (shape / color / labelXY / plantKey / badge / dims / where / desc).

3 · PLANTS + maps

Add matching PLANTS keys and BED_PLANT_MAPS entries for the clickable dots. Add WATER_BANDS in watering-data.js per new plant or it drops out of the watering guide silently.

4 · Photos

32 HEIC (IMG_4008–4039) → convert to WebP into images/jul-2026/; add a "jul-2026" block to PHOTOS_BY_MONTH keyed by the new zone keys. Keep month keys alphabetical.

5 · Don't forget

Bump every ?v=YYYYMMDD in index.html. Do not reintroduce tweaks-panel.jsx. No build step / no npm.

6 · Deploy

Edits happen in the repo; push runs on Brad's machine: ./deploy.sh "add front garden".
